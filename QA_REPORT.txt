СЛУШАЮ 98 — MOBILE v4 / QA REPORT

КОРНЕВАЯ ПРИЧИНА
----------------
В v3 приложение читало список файлов Яндекс Диска правильно, но затем пересобирало путь к MP3 вручную.
Для публичных папок это ненадёжно: Yandex Public API уже возвращает точный item.path, который нужно использовать
при запросе /public/resources/download. Из-за неверного path API мог вернуть не тот ресурс/ошибку, а Safari получал
невалидный media source — поэтому duration оставался 0:00 и Play падал.

ЧТО ИСПРАВЛЕНО
---------------
1. Сохраняется raw item.path из ответа Yandex API и пробуется первым без изменений.
2. Затем пробуются совместимые варианты path (нормализованный, с ведущим / и без него).
3. /public/resources/download теперь вызывается для конкретного файла по exact path.
4. Metadata `file` используется только как fallback, а не как основной источник.
5. Для Yandex download URL пробуется исходный URL и вариант disposition=inline.
6. Если iOS Safari всё равно отвергает поток, глава загружается в Blob и проигрывается как локальный blob: URL.
7. Play отключён, пока новая глава подключается, чтобы пользователь не запускал пустой/старый src.
8. При нажатии Play сначала вызывается audio.play() непосредственно в пользовательском click-handler — это важно для iOS.
9. При истёкшей временной ссылке приложение запрашивает новую и готовит дорожку заново.
10. Состояние v3 автоматически мигрирует в v4.

ОГРАНИЧЕНИЕ QA-СРЕДЫ
--------------------
В этой среде невозможно провести живой сетевой media-test именно через iOS Safari и пользовательский Yandex downloader URL.
Поэтому сетевой слой проверен по API-контракту, path-логике и fallback-цепочке, а окончательный live media-test должен пройти
на реальном iPhone после публикации. Если Yandex сам включит лимит публичных скачиваний, приложение теперь покажет точную
media/API ошибку вместо абстрактного «Play не работает».
