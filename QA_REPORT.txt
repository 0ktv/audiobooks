СЛУШАЮ 98 v5 — QA REPORT

Причина ошибки v4
-----------------
GitHub Pages — статический origin. Яндекс Диск отдаёт временный download URL на другом origin.
iOS Safari не смог использовать этот URL как media stream, а JS fetch() не смог прочитать MP3 body из-за CORS.
Blob fallback поэтому также падал.

Решение v5
----------
Добавлен Cloudflare Worker audio gateway:
GitHub Pages -> Worker -> Yandex Disk download API -> Yandex downloader -> Worker -> Safari audio

Worker:
- принимает public_key + path;
- пробует path как пришёл от Yandex и нормализованные варианты public:/x -> /x -> x;
- серверно получает свежий href через /public/resources/download;
- проксирует Range / If-Range / If-None-Match;
- сохраняет HTTP 206 и Content-Range;
- выставляет корректный audio MIME;
- Content-Disposition: inline;
- CORS разрешён только для https://0ktv.github.io;
- не является произвольным open proxy.

Browser E2E
-----------
Подготовлен локальный E2E сценарий folder -> metadata -> Range MP3 -> duration -> Play -> dark playlist.
В текущем sandbox Chromium блокирует loopback navigation политикой администратора (ERR_BLOCKED_BY_ADMINISTRATOR),
поэтому фактический Safari/WebKit live-test остаётся финальным тестом на iPhone после развертывания Worker.

Важное отличие
--------------
v5 больше НЕ полагается на публичные CORS proxy для MP3. Аудио стримится через собственный Worker с Range support.
